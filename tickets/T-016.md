# T-016 · Batch multi-name backtest runner (Reporting & Portfolio Analytics Epic)

**Epic:** Reporting & Portfolio Analytics · **Owner:** coder → sr-dev review · **Status:** To Do

## Goal
`run_report.py` runs ONE symbol per invocation and writes one report. @user wants "our
strategy vs buy & hold" across the pilot universe in a single view — a batch runner that runs
every pilot name through the engine under T-012, computes metrics + verdict for each against its
own buy & hold baseline, and emits a cross-name comparison table plus per-name reports. This is
the immediate "building performance reports on our strategy vs buy&hold" work; it is orthogonal to
the T-015 signal-direction fork (reporting shape doesn't depend on which signal we ship).

## Deliverables
1. `backtest/run_batch.py` — runs all pilot symbols `[GC=F, NEM, VRT, XOM, SMH]` in one pass
   through the T-010 engine under the T-012 PointInTimeProvider; computes T-013 metrics +
   Buy/Hold/Sell verdict for each vs its buy & hold baseline. (New file, or an additive `--batch`
   flag on run_report.py — coder's choice — but output format must match.)
2. Cross-name comparison table in `reporting/BATCH-REPORT.md`: per name → net return, CAGR,
   Sharpe, Sortino, max DD, exposure, trades, edge vs buy & hold, verdict; plus a "beat count"
   (how many of the 5 names it beats).
3. Per-name report files in `reporting/` reusing the existing HEADER template so they are
   byte-format-compatible with BACKTEST-REPORT.md.
4. Machine-readable: `reporting/backtest_results_batch.json`.

## Acceptance / sr-dev checks
- Runs end-to-end on all 5 symbols with no manual edits; exits 0 (a symbol yfinance can't
  resolve is skipped with a clear note, not a crash).
- Cross-name table renders in BATCH-REPORT.md with every metric + verdict per name.
- Per-name reports match the existing BACKTEST-REPORT.md format — reuse engine/metrics/monte_carlo
  verbatim; no new metric math.
- Every run goes through PointInTimeProvider; tests/test_backtest.py still green (no lookahead
  introduced).
- Deterministic: fixed MC seed so reports reproduce across runs.

## Notes / constraints
- Depends on T-010/011/012/013/014 (all shipped). SMH is a VanEck semis proxy, not an equity —
  label it as such.
- Keep the runner thin: it orchestrates engine.run + compute_metrics + compare_to_buy_and_hold.
- T-017 will consume this runner's per-name equity curves — keep the output shape stable for it.
