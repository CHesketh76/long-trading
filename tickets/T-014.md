# T-014 · Monte Carlo simulation engine (Backtest Epic)

**Epic:** Backtesting & Monte Carlo · **Owner:** coder → sr-dev review · **Status:** To Do

## Goal
Per @user: "maybe a Monte Carlo simulation. In order to judge the performance." Run many simulated paths over the strategy's return distribution + verdict outcomes to produce confidence intervals on metrics, so we know how robust the edge is — not just a single point estimate.

## Deliverables
1. `backtest/monte_carlo.py` — resamples/replays the backtest under perturbation (e.g., bootstrap of daily returns, or parameter jitter) for N paths; computes distribution of each metric (Sharpe, max drawdown, hit-rate on Buy/Hold/Sell verdicts).
2. Confidence intervals: report P10/P50/P90 for key metrics so performance is stated as a range, not a single number.
3. Integration with T-013: uses the same clean data + verdict labels; runs only after T-012 gate passes.
4. Output: MC summary (mean ± CI per metric) consumable by reports and dashboards.

## Acceptance / sr-dev checks
- N paths run reproducibly (seeded); CIs are finite and non-degenerate.
- MC uses identical clean-data contract as the point estimate — no leakage between sim paths.
- Results feed T-013's report format without reformatting.

## Notes / constraints
- Depends on T-010/T-011/T-012/T-013. This is the last card in the epic — it only makes sense once metrics + verdicts exist to simulate over.
- Keep runtime bounded; document default N and per-path cost so it doesn't blow up CI.
