# T-001 · Repo scaffold + storage schema (Phase 0 Foundation)

**Epic:** Phase 0 — Foundation · **Owner:** coder → sr-dev review · **Status:** To Do

## Goal
Establish the repo layout, Python env, and durable storage schema for events/theses/decisions.
Storage is side-agnostic: use Postgres tables (primary), with Parquet on object storage for price/series history. Leave a clear seam so adapters can be swapped without touching schemas.

## Deliverables
1. `pyproject.toml` — Python 3.12, deps: pandas, numpy, sqlalchemy, psycopg2-binary, pydantic, requests, python-dotenv. Dev deps: pytest.
2. Package layout: `macroscope/` (core), `ingestion/`, `storage/`, `signals/`, `reporting/`, `tests/`.
3. Storage schema (Postgres) — tables with columns + types + brief rationale:
   - `events(event_id PK, published_at timestamptz, retrieved_at timestamptz, seq BIGINT NOT NULL DEFAULT nextval('events_seq'), source_ids[], url, raw_text, language, source_tier int, event_type text, entities jsonb, direction_assertions jsonb, numbers_extracted jsonb, novelty_score float8, extractor_confidence float8, prompt_hash text)`
   - `event_revisions(event_id, revision_at, first_print bool, revision_jsonb)` — macro releases stored as first-print + revision chain; models see ONLY the first print plus later revisions as separate, later-dated events.
   - `theses(thesis_id PK, ticker, action text, conviction float8, projected_hold_days int, status text, created_at, updated_at)`
   - `decisions(decision_id PK, thesis_id FK, human_decision text, reason text, edited_params jsonb, at timestamptz)`
   - `source_registry(source_id PK, name, type, cadence, tier float8, url_template, config jsonb)`
4. Pydantic models mirroring the EventObject schema from design-doc §5.1 (strict JSON schema).
5. A small SQLite-backed dev seed so tests run without Postgres; production path documented in README.

## Acceptance / sr-dev checks
- `pytest` green on a seeded local DB.
- Every numeric field typed; no free-form blobs where structured types exist.
- Vintage discipline baked into schema (revisions table present, no silent overwrite).
- README documents env setup + how to point at Postgres vs SQLite dev mode.

## Notes / constraints
- No hardcoded secrets — `.env` only, gitignored.
- **seq + published_at are first-class, not cosmetic:** `seq BIGINT` (monotonic via sequence) is the tiebreaker for point-in-time ordering when two events share a `published_at`; sr-dev must confirm both columns exist and are indexed before sign-off. These are exactly what T-002's vintage layer joins on and what tech-writer mirrors in §5/§14 — if they're an afterthought here they show up as a doc gap there.
- Keep the Parquet layout documented now even if adapters come later; vintage tagging (T-002) depends on it.
