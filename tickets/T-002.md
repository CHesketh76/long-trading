# T-002 · Vintage / point-in-time tagging layer (Phase 0 Foundation)

**Epic:** Phase 0 — Foundation · **Owner:** coder → sr-dev review · **Status:** To Do

## Goal
Build the provenance/vintage layer that makes §14 backtesting honest. Any dataset that can't prove its vintage is quarantined out of backtests. This is the highest-risk ticket in Phase 0 — sr-dev owns the audit-trail check.

## Deliverables
1. `vintage.py` — a tagging utility that stamps every ingested item with:
   - `published_at` (UTC, publisher-stated) vs `retrieved_at`
   - `vintage_ok` bool + `quarantine_reason` when it can't be proven point-in-time
2. Dedupe within 48h windows using SimHash (text) / embedding clustering; keep earliest + highest-tier copy; propagate a cluster ID so "same story, 40 outlets" counts once (§4.2).
3. Macro-release revision handling: store first-print + revision chain as separate later-dated events — no silent overwrite. Wire into T-001's `event_revisions` table.
4. Quarantine rule engine: a function that flags items whose provenance can't be established (missing published_at, retrieved_at < published_at, source tier unverifiable) and routes them to a quarantine bucket rather than the live corpus.

## Acceptance / sr-dev checks
- Dedupe verified: 3 near-duplicate items across outlets collapse to 1 cluster with earliest+highest-tier kept.
- Revision chain: feeding a revised CPI print produces two dated events, not one overwritten row.
- Quarantine bucket is non-empty when given unproven-vintage inputs; live corpus never contains quarantined rows.
- Audit trail: every stamped item carries the fields above and is reproducible (prompt hash from T-001 where extraction applies).

## Notes / constraints
- Depends on T-001 schema (revisions table, source tier column).
- No lookahead possible by construction — this layer exists solely to enforce it.
