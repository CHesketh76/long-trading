# T-012 · No-cheating / lookahead filter (Backtest Epic — INTEGRITY GATEKEEPER)

**Epic:** Backtesting & Monte Carlo · **Owner:** coder → sr-dev review · **Status:** To Do

## Goal
The gating gatekeeper. Per @user: "add some filtering logic to ensure the algorithm is not cheating." This enforces point-in-time discipline so no future information leaks into any decision. sr-dev treats this as a hard gate — before ANY metric in T-013/T-014 is trusted, T-012 must pass.

## Deliverables
1. `backtest/vintage_filter.py` — a filter that runs on every data source feeding the backtest:
   - Rejects any series/row whose published/retrieved vintage can't be proven point-in-time (routes to quarantine).
   - Enforces no-lookahead: at decision time t, only information with timestamp ≤ t is visible. Any signal/event/price that arrives after t is stripped before the strategy sees it.
   - Detects survivorship bias: names removed from a universe after their removal date can't be traded post-removal; constituents must be as-of-date.
2. A "cheat detector" unit test suite: deliberately inject known lookahead violations (future price, future event) and assert the filter catches/rejects them. If these tests fail, the whole backtest is invalid — this is non-negotiable.
3. Integration hook into T-010's data provider contract: the point-in-time guarantee is enforced here, not assumed.

## Acceptance / sr-dev checks (GATING)
- Injected lookahead violations are caught and quarantined by every test in the cheat-detector suite.
- A backtest run with the filter active produces identical results to a "clean" run only when no cheating exists; any injected leak changes the result (proving the filter is doing work).
- Survivorship bias check: a name that delisted during the window cannot be traded after its delist date.
