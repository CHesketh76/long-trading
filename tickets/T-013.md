# T-013 · Performance metrics + Buy/Hold/Sell verdict in reports (Backtest Epic)

**Epic:** Backtesting & Monte Carlo · **Owner:** coder → sr-dev review · **Status:** To Do

## Goal
Compute and report performance, and — per @user's explicit ask — emit a final **Buy / Hold / Sell** verdict at the end of every report so the model has a concrete scoring target. Metrics must be computed only on validated (T-012-clean) data.

## Deliverables
1. `backtest/metrics.py` — Brier score + reliability curves, precision within conviction bands ("when we say ≥70%, how often did it happen?"), Sharpe/Sortino, max drawdown, turnover, cost drag (5–15 bps/side). Per-signal ablation: drop one signal, measure degradation.
2. **Buy/Hold/Sell verdict** — a function that maps the strategy's calibrated outcome + edge into a single final decision per name/window. This is @user's required report field and doubles as the label for scoring model performance.
3. Report integration — the verdict appears at the end of every generated report (aligns with §11 template; tech-writer to byte-align once code ships).
4. Comparison output: strategy vs buy & hold baseline on identical dates (T-011), so beating the baseline is explicit.

## Acceptance / sr-dev checks
- Every metric computed only on T-012-clean data (assert filter ran first).
- Buy/Hold/Sell verdict present in every report and reproducible from documented inputs.
- Baseline comparison renders: strategy vs buy & hold per name, with the beat/miss explicit.

## Notes / constraints
- Depends on T-010 (engine) + T-011 (baselines) + T-012 (integrity gate).
- The verdict label is what T-014's Monte Carlo simulates over — keep it stable and documented.
